# Cat Codex Switcher

Застосунок для Windows, який зберігає кілька акаунтів Codex, перемикає активний вхід і показує ліміти використання у вікні та системному треї. Ядро й інтерфейс написані на Rust із egui/eframe та WGPU.

Персональна реалізація за Windows-версією Codex Account Switcher 0.1.25. Неофіційний проєкт, не продукт OpenAI.

## Можливості

- Додавання акаунтів через браузер або з поточного входу Codex.
- Перемикання акаунтів із перевіркою входу та перезапуском Codex Desktop.
- Відображення тижневих лімітів і, за наявності, окремого 5-годинного вікна.
- Робота у системному треї, один екземпляр програми та автозапуск із Windows.
- Імпорт сумісних профілів і налаштувань з оригінального Switcher.
- Українська, англійська, російська та системний вибір мови. Для інших системних мов використовується англійська.
- Перевірка оновлень із заданого GitHub-репозиторію.

## Запуск

Потрібні Windows 10/11 x64, графічний драйвер із підтримкою WGPU та встановлений Codex runtime. Власні .NET, Swift, Node.js і WebView програмі не потрібні. Системні Windows DLL та браузер використовуються через Windows API. EXE не підписаний.

Зберіть програму за інструкцією нижче та запустіть `target/release/Cat-Codex-Switcher.exe`. Якщо у вас уже є локальний portable-пакет, запускайте `dist/Cat-Codex-Switcher.exe`. Папка `dist/` не входить до Git-репозиторію; клонування завантажує вихідний код без готового EXE.

Додайте акаунти через браузер у розділі «Керування» або зареєструйте поточний вхід Codex. Виберіть неактивний акаунт у списку й підтвердьте перемикання. Завершіть активні завдання Desktop перед підтвердженням. Програма штатно закриє Desktop, збереже поточний вхід, активує й перевірить вибраний, тоді відкриє Desktop. Уже запущені CLI-сесії зберігають свій стан.

Закриття вікна залишає програму у треї. Ліва кнопка на іконці відкриває вікно; права — меню з виходом. Повторний запуск відкриває вже наявне вікно. Поки триває операція з акаунтами, вихід заблокований; очікування браузерного входу можна скасувати кнопкою «Скасувати» або клавішею Esc. Закриття браузера саме по собі не скасовує вхід.

## Дані й імпорт

- Власні дані: `%LOCALAPPDATA%\Cat Codex Switcher\`.
- Активний вхід: `CODEX_HOME`, або `%USERPROFILE%\.codex`.
- Пошук runtime: `CODEX_CLI_PATH`, потім PATH і `%LOCALAPPDATA%\OpenAI\Codex\bin\<version>\codex.exe`.
- Desktop: Store-пакет `OpenAI.Codex` або стандартні папки інсталяції. Для нестандартної інсталяції задайте `CODEX_DESKTOP_PATH`.

У «Керування» виберіть папку оригіналу, перегляньте список імпорту й підтвердьте. Імпорт перевіряє профілі та credentials, пропускає дублікати, копіює сумісні налаштування й кеш. Він не перемикає поточний вхід та не змінює файли джерела. Автозапуск, джерело оновлень і журнал експерименту залишаються власними. Непідтримувана мова імпорту замінюється українською.

Перед роботою з акаунтами закрийте оригінальний Switcher через його меню виходу. Програма використовує сумісний mutex для стандартного сховища оригіналу або `CODEX_SWITCHER_DATA_HOME`, а при імпорті — для вибраної папки. Невідомі сторонні програми, що змінюють той самий `auth.json`, цей mutex не враховують.

Credentials зберігаються локально як повні `auth.json`, із DACL поточного користувача та атомарною заміною. Видалення звичайне, без гарантії стирання копій із резервних сховищ. Локальні JWT-claims використовуються для зіставлення ідентичностей; автентифікацію виконує Codex runtime.

## Ліміти, експеримент та оновлення

Ліміти оновлюються при запуску, відкритті вікна та кожні п’ять хвилин. Останні успішні значення зберігаються при помилках. Необов’язковий рядок за 5 годин відображається лише для точного 300-хвилинного вікна. Дата підписки — знімок зі збереженого входу, не перевірка поточної оплати.

Експеримент спостерігає за додатковими скиданнями за 10, 5 і 1 хвилину до завершення строку. `reset-expiry-experiment.jsonl` містить локальні знімки й рішення `would_attempt`, але програма не виконує й не витрачає скидань. Журнал може містити назви акаунтів та їхні ліміти; токени в нього не записуються.

Для власних оновлень укажіть `owner/repository` у налаштуваннях. Перевірка ручна або щогодини, якщо її ввімкнено. Порожнє джерело не створює мережевих запитів. Підходять стабільні релізи `vMAJOR.MINOR.PATCH` з asset `Cat-Codex-Switcher.exe`. Нова версія відкривається у браузері для ручної заміни після виходу. Релізи оригіналу не є оновленнями цієї програми.

## Збірка та перевірки

Потрібні Rust stable для `x86_64-pc-windows-msvc` і Visual Studio C++ Build Tools із Windows SDK. Версії залежностей зафіксовані в `Cargo.lock`. Налаштування Cargo статично компонують CRT.

```powershell
git clone https://github.com/cat-fire1/Cat-Codex-Switcher.git
cd Cat-Codex-Switcher
cargo fmt --check
cargo test --locked --all-targets
cargo clippy --locked --all-targets -- -D warnings
cargo build --locked --release --bin Cat-Codex-Switcher
.\target\release\Cat-Codex-Switcher.exe
```

Готовий файл після збірки: `target/release/Cat-Codex-Switcher.exe` (або відповідний шлях у `CARGO_TARGET_DIR`, якщо його задано). Для portable-пакета скопіюйте EXE в `dist/` разом із `LICENSE` і повідомленнями ліцензій залежностей. `build.rs` додає іконку та властивості Windows EXE.

## Структура проєкту

| Шлях | Призначення |
|---|---|
| `src/main.rs`, `src/ui.rs`, `src/windows_style.rs` | Запуск і віконний інтерфейс |
| `src/model.rs`, `src/store.rs` | Моделі, збереження акаунтів, імпорт і перемикання |
| `src/rpc.rs`, `src/worker.rs` | Codex runtime та фонові операції |
| `src/platform.rs`, `src/tray.rs` | Інтеграція з Windows і системний трей |
| `src/i18n.rs` | Переклади інтерфейсу |
| `src/updates.rs`, `src/experiment.rs` | Перевірка оновлень та журнал спостережень |
| `assets/` | Логотипи й іконка застосунку |
| `PARITY.md` | Історичний звіт про відповідність оригіналу та перевірки |

## Стан перевірок

Регресійні тести перевіряють вихід після зупинки worker, відновлення Desktop після помилок перемикання та продовження оновлення збережених профілів при пошкодженому активному вході. Тести використовують підставні операції й тимчасові дані, без реальних акаунтів. Файлова перевірка потребує права встановлювати DACL у тимчасовій папці. Попередні перевірки описані в [PARITY.md](PARITY.md); їхній код доступний в історії Git. Цей звіт не є гарантією перевірки кожної поточної ревізії.

Реальний браузерний вхід та handoff слід остаточно перевірити в окремому Windows-профілі з тестовими акаунтами. Відомості про попередні перевірки зберігаються в історії Git.
