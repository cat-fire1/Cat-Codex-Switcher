# Проверки и оптимизация — 2026-11-15

Исходная ревизия: `2bbe531`. Изменения проверены локально на Windows x64,
Node.js 26.12.1, Rust/Cargo 1.99.1. Реальные аккаунты, вход через браузер и
переключение установленного Codex Desktop в этих проверках не использовались.

## Методика и границы

- Операция: N последовательных публикаций полного состояния для N профилей,
  как в цикле обновления лимитов. Фикстуры: 1, 5 и 20 искусственных профилей.
- Метрика: миллисекунды на цикл; медиана 7 выборок, по 10 циклов в каждой.
- Сборка теста: debug, одинаковая для исходного и оптимизированного пути.
- Создание фикстур, RPC/сеть, запись кеша лимитов и обновление настоящего трея
  исключены из измеряемого участка. Это не время полного обновления приложения.
- Бюджет поиска: один вариант реализации — кеш метаданных подписки в пределах
  одного обновления; два контрольных прогона после изменений. Параллелизм сети
  не включался.
- Условия принятия: регрессии хранения/ротации токенов и идентичности остаются
  зелёными, результаты snapshot совпадают, сборка проходит, улучшение повторяется.

## Результаты

До изменения реализации: `cargo test --locked --offline` — **36 passed**.
`npm run build` — успешно, 2,82 с по внешнему таймеру. Две добавленные проверки
настроек затем воспроизвели ошибки: **2 failed** на старой реализации.

Первоначальный замер старого кода, ещё до включения кеширования:

| Профилей | Медиана цикла, мс |
|---:|---:|
| 1 | 0,2420 |
| 5 | 6,0780 |
| 20 | 101,8929 |

После изменений тест сохраняет оба пути: `uncached` повторяет чтение на каждой
публикации; `batch` кеширует метаданные внутри цикла. Их порядок чередуется,
а сериализованные snapshot проверяются на равенство. Кеш начинается пустым в
каждом измеряемом цикле; его первоначальное заполнение включено во время.

| Профилей | Контроль 1: uncached → batch, мс | Контроль 2: uncached → batch, мс | Ускорение во втором контроле |
|---:|---:|---:|---:|
| 1 | 0,2440 → 0,2469 | 0,2427 → 0,2483 | примерно без изменения; +0,0056 мс |
| 5 | 6,0694 → 1,3305 | 6,0843 → 1,3271 | 4,58× |
| 20 | 106,8069 → 10,9507 | 100,6497 → 10,5543 | 9,54× |

Диапазоны min–max выборок во втором контроле:

| Профилей | uncached, мс | batch, мс |
|---:|---:|---:|
| 1 | 0,2409–0,2537 | 0,2463–0,2532 |
| 5 | 6,0330–6,1852 | 1,3200–1,3329 |
| 20 | 99,5597–103,2534 | 10,4241–11,2737 |

При одном профиле есть небольшой накладной расход. При 5 и 20 профилях
улучшение устойчиво. Оно относится только к измеренному участку; общий выигрыш
с сетью и ротацией credentials будет другим. В рабочем refresh метаданные
обработанного профиля дополнительно перечитываются после RPC, включая ошибку
или отмену, чтобы не показывать сведения до ротации токенов.

Пробный замер одновременно с release-компиляцией дал для 20 профилей
123,67 → 13,60 мс; он исключён из итогового сравнения из-за фоновой нагрузки.

Новые проверки покрывают актуальность и сброс черновика настроек, блокировку

во время операций, отмену refresh с join, завершение тестового RPC-процесса
после отмены входа, доставку Windows-события активации, выбор процента трея,
генерацию иконки и обновление метаданных подписки после имитации ротации.
Старые проверки сохранения токенов при ошибке/отмене и отката импорта проходят.

## Что изменено

- Выход проходит проверку состояния worker, прекращает refresh и ждёт его
  завершения перед закрытием процесса. Новые команды после начала выхода
  отклоняются; постановка команды и начало выхода синхронизированы.
- Добавлены отмена браузерного входа, блокировка повторных действий и показ
  ошибок IPC. Настройки получают свежий черновик при каждом открытии.
- Трей показывает процент активного аккаунта и время получения данных;
  повторный запуск активирует существующее окно. Открытие из трея запрашивает
  обновление, если worker может принять команду.
- Кешируются только сведения о подписке, без credential bytes и токенов.
  Кеш ограничен одним обновлением; атомарные записи credentials сохранены.
- Ссылка релиза проверяется и открывается Windows API без `cmd /C`.
  В release включена CSP; для dev сохранён режим без CSP.
- `build.cmd` сохраняет сборочные кеши. README соответствует Tauri/WebView2.

## Воспроизведение

```powershell
npm ci
npm test
npm run build
cargo test --locked --offline
cargo test --locked --offline benchmark_publish -- --ignored --nocapture
npx tauri build --no-bundle
```

Для первого скачивания отсутствующих Rust-зависимостей уберите `--offline`.
Измерения запускайте после окончания сборки, без параллельной компиляции.
Исходный вариант доступен в ревизии `2bbe531`; изменения относительно него
можно посмотреть командой `git diff 2bbe531 HEAD` после коммита.

Полный GUI-прогон готового EXE, фактическое отображение трея и реальный
OAuth/handoff требуют отдельной проверки с тестовым Windows-профилем.
Приведённые результаты не измеряют старт, RAM, p95 сети или суммарное время
переключения аккаунта. Ускорение повторной сборки за счёт сохранения кешей
также отдельно не измерялось.
