# Відповідність Windows-оригіналу

Еталон: Windows WPF-клієнт і Swift SwitcherCore у цьому дереві, версія 0.1.25 з `windows/Directory.Build.props`. Особиста Rust-версія має власну версію 0.1.0. Оригінальні джерела збережені.

## Матриця

|---|---|---|
| Вхід через браузер та скасування | `rpc`, `worker` | Дочірній RPC-fixture, рання нотифікація входу, скасування очікування |
| Реєстрація поточного входу, автоматичне визначення акаунта | `store`, `model` | Вигадані credentials, збереження та повторне завантаження |
| Дублікати й різні workspace одного email | `model`, `store` | Зіставлення ID та регістронезалежного email, відмова дубліката |
| Видалення неактивного акаунта | `store` | Захист активного профілю, відновлення списку після відмови видалення |
| Підтвердження перемикання та видалення | `ui` | Окремі fixture-екрани UA/EN/RU |
| Штатне закриття Desktop, без завершення CLI | `platform::Desktop` | Win32-вікно спеціального fixture-EXE, точне зіставлення шляху |
| Пошук Store-інсталяції та AUMID | `platform::Desktop` | Native PackageManager і manifest XML; реальний Store-handoff не виконувався |
| Послідовність close/save/activate/verify/commit/reopen | `store::handoff` | Успішний порядок і помилки на кожній межі |
| Відновлення після verify/commit | `store::handoff` | Попередній вхід, перша активація без попереднього входу, помилка самого відновлення |
| Перезапуск Desktop | `platform::Desktop` | Реальне закриття й відкриття fixture-EXE; враховано гонку завершення процесу |

| Перевірка ідентичності входу | `model`, `rpc` | Локальні claims, різні workspace, розбіжність RPC і credentials |

| Кількість додаткових скидань | `model` | Невідомі/від’ємні значення та невалідні деталі |
| Дата підписки та час знімка | `model::subscription`, `ui` | Перевірка власника й дати; інформація доступна також без відповіді usage |
| Кеш і збереження останніх даних при помилці | `store`, `worker` | Персистентність кешу, stale-представлення на fixture-екранах |
| Оновлення лімітів на старті, відкритті й кожні 5 хвилин | `worker` | Реалізовано в одному worker; RPC-перевірки не звертаються до реального сервісу |
| Відсоток/логотип і tooltip трея | `tray` | Створення справжнього Windows tray icon, обидві теми, 0/9/10/99/100%, доставка кліку |
| Згорнення в трей й активація | `ui`, `tray::Shell` | Fixture-вікно: --background, close-to-tray, повторний запуск, лівий клік, Quit |
| Один екземпляр та сумісний mutex оригіналу | `platform` | Окремі дочірні процеси та named events/mutex |
| Автозапуск і негайні налаштування | `platform::startup`, `worker`, `ui` | Компіляція native registry API, збереження налаштувань; вхід у Windows заново не виконувався |
| Спостереження строку скидань | `experiment` | Контрольні точки 10/5/1, missed/read_failed, відновлення з журналу, resetAttempted=false |

## Архітектурні відмінності

- WPF і Swift host замінені ядром Rust та egui/eframe 0.31.1 з WGPU. Вигляд близький до оригіналу, без обіцянки піксельної тотожності WPF.
- UI, worker та Windows message loop трея окремі. Свіжий presentation snapshot спільний між UI і shell; токенів у ньому немає. Іконка та активація працюють із прихованим GPU-вікном.
- Власне сховище й особисте джерело оновлень. Порожній репозиторій означає «не налаштовано». Оновлення оригіналу не пропонуються як Rust-оновлення.
- Англійську збережено; додано українську й російську за побажанням користувача. Китайську замінено цим набором.
- Імпорт джерела повторно перевіряє профілі при підтвердженні; зміна складу preview вимагає нового перегляду. Відсутні старі accountID виводяться з credentials без запису в джерело.
- Функції лише macOS, зокрема Tibo forecast та Sparkle, не входять до обраного Windows-обсягу.

## Перевірки та межі

Автоматизовані перевірки використовують вигадані акаунти й тимчасові папки. Native Desktop-тест запускає тільки `rpc-fixture.exe`. Lifecycle-тест запускає справжній eframe EXE з `--ui-fixture --shell-fixture`: worker акаунтів у цьому режимі відсутній.

Перелік перевірок: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --all-targets` (44 тести), release-збірка, packaged `--self-test`, перевірка Windows x64 PE та статичного CRT, 38 знімків інтерфейсу. Пакет має журнали self-test і binary-check та файл контрольної суми поруч із EXE.

Після перегляду користувач попросив відтворити дизайн Windows-оригіналу. Інтерфейс перероблено за MainWindow.cs та App.xaml: ширина 420 логічних пікселів, автоматична висота, Segoe UI, заголовок 20 px, текст 13 px, назва акаунта 14 px, деталі 10.5 px. Замість вкладок і карток — командний рядок, плоский список з аватарами 32 × 32, індикатор активного рядка 3 × 24, смуги лімітів у рядках, керування й підтвердження зі стрілкою «Назад». Палітра light/dark і відступи взяті з коду оригіналу. Додаткові власні функції імпорту й налаштування джерела оновлень доступні в розгортаних секціях. Цифри трея залишені збільшеними за попереднім запитом. Рендерер — egui, тому це відтворення компонування та поведінки, а не WPF-контроли.

Додано три інтерактивні UI-перевірки: кліки по всій площі рядка, захист активного/зайнятого рядка, кнопки керування й налаштувань, перехід до видалення та повернення, ширина сторінок для UA/EN/RU. Візуальні знімки генеруються також з необов’язковим 5-годинним рядком. Порівняння зроблено з локальними джерелами оригіналу; запущений WPF-оригінал не використовувався як піксельний еталон.

Реальний браузерний OAuth, відповіді живого сервісу, handoff справжнього Codex Desktop, наступний вхід у Windows для автозапуску, окрема Windows 10 VM та screen-reader-сесія не перевірені. Для завершення цих перевірок потрібні окремий Windows-профіль і тестові акаунти. Реальні credentials користувача під час цієї роботи не читалися й не перемикалися.

Безпекова межа відповідає оригіналу: локальні файли й права користувача. Інші програми цього ж користувача або резервні копії можуть читати credentials. Після успішного commit, але невдалого запуску Desktop вибраний акаунт залишається активним; повідомлення просить відкрити Desktop вручну. Повної crash-recovery транзакції чи журналу відновлення активних credentials немає, як і в оригіналі.
